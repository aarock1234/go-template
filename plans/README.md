## Decisions made while planning

- 004 binds the database to loopback and keeps the default development
  credentials. Requiring a password variable would make `make db` fail on a
  fresh checkout, and with a loopback binding the defaults are not exposed.
- 003 keeps the `github.com/aarondl/null/v9` overrides and documents the
  needed `go mod tidy` beside them, rather than choosing a different
  nullable-type library for the maintainer.
- 005 does not make setup's file rewrites atomic. Four small files in the
  working directory failing to write is very unlikely, and the tool cannot be
  rerun usefully once markers are stripped.
- 007 covers `README.md` only. `STYLE.md` and `AGENTS.md` also cite removable
  files, but they are untracked work in progress.
- 009 leaves two readers of `.env` (the application, and the shell for
  migration targets only) and documents the quoting rule that makes them
  agree. A single reader would need a Go migration command.

## Findings considered and rejected

- CI has no formatting check: believed wrong. A golangci-lint v2 `run` reports
  the formatters configured under `formatters`, so the sentence at
  `.agents/skills/go-style/references/workflow.md:107` is the likelier error.
  Not confirmed against the v2.14.0 documentation.
- Backoff computes NaN when the initial delay is zero
  (`pkg/retry/retry.go:158`): needs about 1,024 attempts to trigger.
- `Save` returns an error after a successful rename when the directory fsync
  fails (`pkg/state/state.go:129-135`): rare, and the new state is durable in
  practice.
- Pinning container images by digest: more maintenance than a template's
  development stack warrants.
- The CI test step runs with no test files: harmless, and correct the moment
  a scaffolded project adds tests.
- Docker module and build cache mounts: unmeasured, minor.
- Draining response bodies before close in `pkg/template/request.go`: low
  confidence that fphttp's transport behaves like `net/http` here.
- Server timeouts can be configured to zero and there is no request-body
  limit: defaults are safe and no handler reads a body.
- The dev Docker stage runs as root: development stack only.
- Two error-to-status mechanisms in `pkg/apperr` and `pkg/handler`: plausibly
  a deliberate showcase.
- Hand-listed package and hosting names in the setup doc comment and README:
  latent drift only; plan 007 removes the README copy from scaffolds.
- Inline comments in `.env` values are not supported by `pkg/env`: the loader
  never claimed to support them.
- Undocumented make and POSIX shell prerequisite: minor documentation.
- Untracked `AGENTS.md` and `STYLE.md` linked from the README: maintainer work
  in progress, not a defect.
